## Три задачи вместо прежнего акцента на матрице

1. **Данные для сценариев сайта.** Получать через согласованный backend-доступ
   текущую анкету/статус, чтобы понимать, что человек уже сообщил. Доступ к
   базе аналитики бота, который у нас есть, этого сам по себе не обеспечивает.
2. **Долговая ветка.** Выбирать её по запросу или подтверждённому сигналу входа,
   сохраняя отдельный обычный кредитный сценарий. Подготовить страницу чата
   для мобильного трафика и консультационные тексты.
3. **Онлоадер без повторного телефона.** Связать чат с партнёрским обращением,
   использовать уже известный контакт и согласовать один путь передачи лида.
   Контакт может оставаться на backend — боту не обязательно получать сам номер.

Широкая история всех обращений CRM остаётся самостоятельной задачей.
Получение текущей анкеты для сайта/онлоадера — теперь часть критического пути.
Два вида доступа нельзя объединять в бесконтрольное чтение всей базы.

## Что поправлено в плане

| Было | Теперь |
|---|---|
| Получение истории/form-id — необязательный параллельный поток | Текущая анкета сайта/партнёра — обязательная интеграция. Полная история CRM отдельно |
| P0: найти платформу урегулирования | Задача снята с первого этапа. Основное предложение остаётся БФЛ |
| Сначала дождаться витрины и всех посадочных | Готовим простую мобильную страницу с чатом и входной контекст |
| Во всех новых анкетах просим имя/телефон в конце | У новых посетителей — по обычному контракту. На подтверждённом онлоадере контакт повторно не спрашиваем |
| Один вариант отправителя — бот/coordinator | У бота и backend сайта разные возможные обязанности, но для одного обращения всегда один владелец доставки |
| Матрица ограничена долговыми идеями | Добавить кредит/МФО для соответствующего явного запроса, без автоматического увода из долгов |
| A/B анкеты — ближайшая основная работа | Сначала данные, доставка и измерение. Затем отдельные эксперименты анкеты/приветствия и согласия |
| 8–14 дней на прежний набор задач | Оценку не переносим на новый объём: переоценка после контракта Андрея |

## Повторная проверка выводов

- Не выдано поручение Андрею за уже работающий запрос/доступ.
- Бизнес-диапазон 190–299 не выдан за новое чтение production-настройки.
- Описанный 30-дневный холд не перенесён на все окна дедупликации.
- Уведомление по 190 не смешано с явно сказанным согласием по дублям.
- Последующее предложение согласия в чате не объявлено готовым API или
  немедленной заменой страницы для всего трафика.
- Слова о договорах не превращены в финансовую отчётность, а 41/46 — в A/B.
- Расширение кредитного каталога не отменяет долговой фокус конкретного запроса.
- В этой задаче меняется план и документация; код, серверы, отправка лидов
  и сообщения адресатам не выполняются.
