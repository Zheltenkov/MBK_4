# Чипсы на вопросах анкеты — дизайн

Дата: 14.09.2026. Продолжение спеки
`docs/superpowers/specs/2026-09-14-quick-replies-greeting-design.md` (там —
контракт `quick_replies`, виджет и кнопки приветствия; этот блок в ней указан
как «следующий, без правки виджета»). Решение человека 14.09.2026: «Давай».

## Зачем

На закрытый вопрос анкеты человек отвечает одним нажатием вместо набора
текста. Нажатие разбирается без модели — ход не ждёт извлекателя.

## Кнопки

| Поле | Вопрос | Кнопки (`label` = `value`) |
|---|---|---|
| `debts.has_active_credits` | есть ли сейчас кредиты | «Да, есть» · «Нет» |
| `employment.type` | занятость | «По найму» · «Свой бизнес» · «Не работаю» |
| `assets.has_realty` | есть ли недвижимость | «Да, есть» · «Нет» |
| `assets.realty.kind` | тип объекта | «Квартира» · «Дом» · «Апартаменты» · «Коммерческая» |
| `assets.has_second_realty` | есть ли ещё недвижимость | «Да, есть» · «Нет» |
| `assets.has_vehicle` | есть ли автомобиль | «Да, есть» · «Нет» |
| `assets.vehicle.pledged` | авто в кредите/залоге | «В кредите» · «В залоге» · «Чистая» |

Ожидаемые значения нажатий: «Да, есть» → `true`, «Нет» → `false`;
«По найму» → `official`, «Свой бизнес» → `business`, «Не работаю» →
`unemployed`; «Квартира» → `flat`, «Дом» → `house`, «Апартаменты» →
`apartments`, «Коммерческая» → `commercial`; «В кредите» и «В залоге» →
`true`, «Чистая» → `false`.

Без кнопок: шаги анкеты, где спрашиваются два-три поля разом (сумма и
возраст; долг и срок просрочки; форма собственности и собственники; регион и
тип второго объекта; год, марка и модель авто), и свободные ответы (город,
доход, имя, телефон).

## Раздел 1. Данные — матрица

- `routing/schema.py`: модель `QuickReply` (`label`, `value` — непустые
  строки, лишние поля запрещены) и поле `FieldSpec.quick_replies:
  list[QuickReply] | None = None`. Валидатор: кнопки только у `kind` `bool` и
  `enum`, не больше четырёх.
- `routing/matrix.yaml`: `quick_replies` у семи полей из таблицы. Порядок и
  тексты меняются правкой YAML.
- Промпт извлекателя поле не видит: каталог полей берёт из `FieldSpec` только
  `kind`, `values`, `label`, `ask`.

## Раздел 2. Нажатие разбирается без модели

Быстрый разбор (`interpretation/fastpath.parse_expected_answer`) берётся за
ответ, только когда спрошено одно поле, и сравнивает enum-ответ с маркером
целиком по числу слов. Три правки словарей, чтобы каждая кнопка узнавалась:

- `routing/normalize.py`, `_EMPLOYMENT`: маркеры `("по найм", "official")` и
  `("свой бизнес", "business")`;
- `interpretation/fastpath.py`: таблица `_PATH_BOOL_VALUES` для
  `assets.vehicle.pledged` — «в кредите» и «в залоге» → `true`, «чистая» и
  «чистый» → `false`; `_simple_bool` сверяется с ней первой.

Инвариант: тест прогоняет каждую кнопку матрицы через
`parse_expected_answer(value, [path], matrix)` и требует ровно ожидаемое
значение из таблицы. Набор кнопок в матрице обязан совпадать с таблицей теста;
поле с кнопками обязано спрашиваться в `script` отдельным шагом.

## Раздел 3. Когда кнопки показываются

`quick_replies.quick_replies(state, *, enabled, matrix=None)`:

1. `enabled` ложно — пусто (как было: оба флага, `MBK_QUICK_REPLIES` и
   `MBK_ENTRY_ROUTING`).
2. Клиент не написал ни слова — кнопки приветствия (без изменений).
3. Иначе — кнопки вопроса анкеты, если выполнено всё:
   - последняя реплика истории — бота;
   - идёт анкета (`entry_routing.questionnaire_active`), а не ветка развилки;
   - последняя реплика клиента — не прощание (`core.client_is_saying_goodbye`):
     на прощании `core.commit_turn` не обновляет `script.asked`, и без проверки
     под «Всего доброго» висели бы кнопки прошлого вопроса;
   - `script.asked` — ровно одно поле, и у него есть `quick_replies`.

`script.asked` пишет `core.commit_turn` (`_remember_asked`) — поля, о которых
бот действительно спросил на этом ходу. Закрытый разговор отсекает
`main._public_state`, как и раньше.

`quick_replies.py` не импортирует `core` и `entry_routing` на уровне модуля:
оба импортируют его сами. Импорт — внутри функции, где оба модуля уже
загружены.

Контракт (`bubbles.quick_replies`, `state.quick_replies`), виджет `mbk-site`,
наш стенд и `main.py` не меняются: они уже отдают и рисуют любые кнопки.

## Сбои

| Что | Как ведёт себя система |
|---|---|
| нажатие не узнано быстрым разбором | ход зовёт модель, как на набранный текст — медленнее, но верно; тест не даёт этому случиться незаметно |
| бот спросил два поля | кнопок нет |
| прощание посреди анкеты | кнопок нет |
| ветка «уже оставлял заявку» / «не наш профиль» | кнопок нет |
| перезагрузка страницы | кнопки из `state.quick_replies`, как у приветствия |

## Тесты

- схема: больше четырёх кнопок, кнопки у `money`, пустой текст — ошибка
  валидации;
- инвариант разбора каждой кнопки и совпадение набора с таблицей;
- правило показа: одно поле с кнопками, два поля, поле без кнопок, ответ
  клиента в пути, ветка, прощание, выключенный флаг;
- сквозной ход через `core.prepare_turn`/`core.commit_turn`: после вопроса о
  кредитах кнопки «Да, есть»/«Нет»; нажатие «Да, есть» пишет факт без вызова
  извлекателя.

## Что не входит

- аналитика нажатий на вопросах анкеты (событие `quick_reply_used` остаётся
  только за приветствием);
- кнопки на составных шагах анкеты и на свободных ответах;
- правка виджета, стенда и контракта.
