# Общая память Claude Code и Codex

- Статус: дизайн утверждён, реализация не начата
- Дата: 26.08.2026
- Область: рабочий контур разработки, не продакшн-код бота

## Проблема

Разработка идёт двумя агентами попеременно: Claude Code и Codex CLI, оба из
VS Code. При переключении контекст теряется — принимающий агент не знает, что
делал предыдущий, где тот остановился и что оставил намеренно.

Состояние на момент дизайна:

| | Claude Code | Codex |
|---|---|---|
| Память | `~/.claude/projects/c--Users-zvp-VS-projects-MBK-v4/memory/` — 3 файла | `~/.codex/memories/` пуст, `memories_1.sqlite` — 0 записей |
| Инструкции | глобального `CLAUDE.md` нет, проектного нет | `~/.codex/AGENTS.md` — 15 КБ, проектного нет |
| Видимость чужой памяти | читает `~/.codex/**` через `additionalDirectories` | Claude-память не видит |

Память Codex фактически не используется, поэтому переносить нечего — стор
строится с нуля.

## Что синхронизируем

Решено: **durable-факты о проекте плюс состояние работы**. Сырые рассуждения и
транскрипты не переносятся — они дороги по токенам и требуют автозахвата
хуками, которых у Codex нет (в его `config.toml` доступен только
`notify = [..., "turn-ended"]`).

## Решение

Общий файловый стор в репозитории, две точки входа, протокол вынесен на
глобальный уровень.

### Раскладка в проекте

```
MBK_v4/
├── AGENTS.md                  # ссылка на глобальный протокол + repo-специфика
├── CLAUDE.md                  # только импорты, своего текста нет
└── docs/agent-memory/
    ├── MEMORY.md              # плоский индекс: строка на факт
    ├── SESSION.md             # состояние работы, перезаписывается
    └── facts/
        ├── deploy-process.md
        └── mbk-production-setup.md
```

`CLAUDE.md` целиком:

```markdown
@AGENTS.md
@docs/agent-memory/MEMORY.md
@docs/agent-memory/SESSION.md
```

Claude Code разворачивает `@`-импорты в контекст на старте — индекс и состояние
видны без единого вызова инструмента. Codex импорты не поддерживает, но
корневой `AGENTS.md` читает нативно; первым пунктом протокола там стоит
требование прочитать `MEMORY.md` и `SESSION.md`.

Источник протокола — глобальный `PROTOCOL.md` (см. ниже). Корневой `AGENTS.md`
содержит только ссылку на него и repo-специфику: чем этот проект отличается,
какие у него команды проверки, что здесь считается фактом. Правила записи в нём
не дублируются.

Корневой `AGENTS.md` выбран носителем repo-специфики, потому что Codex читает
его нативно и импортов не умеет, а Claude Code втягивает тот же файл через
`@AGENTS.md`. Один текст, оба агента, дублирования нет.

### Глобальный слой

Протокол лежит одним экземпляром вне проектов:

```
C:\Users\zvp\.agent-memory\PROTOCOL.md
```

Подключение выполняется один раз:

| Файл | Изменение |
|---|---|
| `~/.claude/CLAUDE.md` | создать, содержимое — `@C:\Users\zvp\.agent-memory\PROTOCOL.md` |
| `~/.codex/AGENTS.md` | дописать в конец блок «в начале сессии прочитай `PROTOCOL.md` и следуй ему» |

Врезка в Codex ставится в конец файла, рядом с существующей строкой про
приоритет проектного `AGENTS.md` — смысловое место то же.

Если `@`-импорт абсолютным windows-путём не сработает, текст протокола
переносится прямо в `~/.claude/CLAUDE.md`, а нейтральный файл остаётся только
для Codex. Функционально эквивалентно.

### Бутстрап нового проекта

Ручных действий при заведении проекта нет. Протокол содержит правило: если в
репозитории отсутствует `docs/agent-memory/`, первый агент, которому
понадобилось записать факт или передать ход, создаёт каталог, `MEMORY.md`,
`SESSION.md` и оба корневых шима, после чего продолжает работу.

Шимы в репозитории нужны и при наличии глобального слоя: глобальный слой даёт
правила, но не содержимое. Импорты убирают лишнее чтение каждую сессию и
оставляют память привязанной к репозиторию — при клонировании она едет вместе
с кодом.

### Контракт `SESSION.md`

Файл перезаписывается целиком при передаче хода. Append-лог запрещён: история
хранится в git, а растущий файл перестают читать.

Имя `SESSION.md`, а не `HANDOFF.md`, потому что в `docs/` уже есть
`HANDOVER.md` — передача системы человеку-разработчику МБК. Различие в одну
букву при разном смысле недопустимо.

Структура:

```markdown
# Состояние сессии

Обновлён: 2026-08-26 · Агент: claude-opus-5 · Ветка: dev · Рабочее дерево: чисто

## Задача
<1–3 предложения: что делаем и зачем>

## Сделано
- <результат> — <файл:строка или хеш коммита>

## Следующий шаг
- <конкретное действие>

## Открытые вопросы
- <вопрос> → ответ нужен от: пользователя / кода / внешней системы

## Не трогать
- <что оставлено намеренно> — <почему>
```

Правила по полям:

- **Шапка.** Дата, агент, ветка и чистота рабочего дерева. Пометка «грязно
  (N файлов)» предупреждает, что часть работы вне коммитов.
- **Задача.** Что делаем и зачем, не пересказ тикета.
- **Сделано.** Только изменения, реально попавшие в файлы, со ссылкой
  `файл:строка` или хешем коммита. Утверждение без ссылки не пишется —
  принимающий агент не сможет его проверить. Прерванная правка отмечается как
  «частично», а не замалчивается.
- **Следующий шаг.** Конкретное действие, а не направление: «прогнать
  `pytest tests/test_lead_intake.py`», не «продолжить тестирование».
- **Открытые вопросы.** С указанием источника ответа. Пустой раздел остаётся с
  прочерком.
- **Не трогать.** То, что выглядит как дефект, но сделано намеренно. Раздел,
  ради которого система и строится: без него принимающий агент «чинит»
  сознательное решение предыдущего.

Ограничения: не длиннее ~60 строк; без сырых рассуждений, трассировок и
секретов.

Момент записи: перед переключением на другого агента и в конце сессии. Ни один
агент не определяет момент переключения самостоятельно, поэтому в протокол
включён явный триггер пользователя: слова «хендофф» или «сохрани состояние»
означают немедленное обновление `SESSION.md`.

### Формат факта

Личное (кто пользователь, как с ним работать) остаётся в
`~/.claude/projects/.../memory/` и в репозиторий не переносится: репозиторий
клонируется и шарится. В репо-стор идут только знания о проекте.

Формат совпадает с уже используемым, чтобы существующие файлы переехали без
правок:

```markdown
---
name: deploy-process
description: Ручные релизы по SSH, CI нет, скрипта в репозитории нет
metadata:
  type: decision
---

<факт>

**Почему:** <обоснование>
**Как применять:** <когда и что делать>

Связано: [[mbk-production-setup]]
```

Типы: `project` — цели и ограничения работы; `decision` — выбрали X вместо Y и
почему; `gotcha` — грабли, на которые уже наступали; `rule` — как здесь принято
делать; `reference` — внешние ссылки, дашборды, тикеты.

Для `decision`, `gotcha` и `rule` строки **Почему** и **Как применять**
обязательны: факт без обоснования через месяц неотличим от суеверия.

`MEMORY.md` — плоский индекс вида `- [Заголовок](facts/slug.md) — зацепка`.
Он подгружается в контекст целиком, поэтому содержит только строки-указатели.

### Приватность стора

`origin` репозитория — `https://github.com/Zheltenkov/MBK_v4`. Пользователь
подтвердил 26.08.2026, что репозиторий приватный и таковым останется. Это
условие несущее: два переезжающих факта содержат карту боевого контура (адрес
сервера, вход по паролю без ключей, GitLab заказчика с именем его разработчика,
приватный registry), и до миграции ничего из этого в отслеживаемых файлах не
было — проверено `git grep`.

Следствия:

- Факты переносятся без сокращений, включая путь к локальному файлу с
  доступами. Требование пользователя от 26.08.2026: Claude Code и Codex должны
  обладать одинаковыми знаниями по доступам, иначе передача хода неполна — один
  агент знает, где взять учётные данные, а второй нет.
- Различие проведено по границе «указатель против содержимого»: в стор попадает
  путь к файлу, сам файл остаётся в `.gitignore`. Путь без машины пользователя
  бесполезен, значения учётных данных в репозиторий не попадают.
- Паролей, токенов и ключей в сторе не появляется ни при каких условиях —
  правило раздела «Правила записи» действует и для приватного репозитория.
- Если репозиторий когда-либо станет публичным, стор требует ревизии до
  открытия. Пункт вынесен в `AGENTS.md` проекта.

### Граница с `docs/adr/`

В проекте есть каталог архитектурных решений (`docs/adr/`, ADR-0001). Крупные
архитектурные решения остаются там. В `facts/` для них создаётся указатель типа
`reference` со ссылкой на ADR, а не копия текста. Тип `decision` в `facts/`
предназначен для решений, не тянущих на ADR: выбор библиотеки, порядок запуска,
договорённость по процессу.

### Правила записи

1. Записываются: решение с обоснованием, грабли, договорённость, внешний ресурс.
2. Не записывается: то, что видно в коде или `git log`; то, что живёт одну
   сессию; секреты, токены, доступы.
3. Перед созданием файла ищется существующий по теме. Обновление вместо второго
   файла.
4. Неверный факт удаляется вместе со строкой индекса. Пометки «устарело» не
   используются: мёртвые факты хуже отсутствующих.
5. Даты абсолютные («до 2026-09-01»), не относительные.
6. Коммиты памяти отделены от кода, префикс `docs(memory):`. Дифф функциональных
   изменений не зашумляется, память откатывается независимо.

## Обработка отказов

- **Оба агента правили `SESSION.md`.** Перед перезаписью читается шапка. Если
  поле «Агент» указывает на другого и дата сегодняшняя — молчаливая перезапись
  запрещена; разделы сливаются, в шапке перечисляются оба агента.
- **`docs/agent-memory/` отсутствует.** Выполняется бутстрап, работа
  продолжается.
- **Индекс разошёлся с `facts/`.** Файл без строки в `MEMORY.md` невидим для
  Claude Code, так как в контекст подгружается только индекс. Агент, заметивший
  расхождение, исправляет индекс немедленно.

## Проверка

Сценарии, которые прогоняются после реализации:

1. `@`-импорт абсолютным windows-путём в `~/.claude/CLAUDE.md` разворачивается в
   контекст. При отрицательном результате — запасной вариант из раздела
   «Глобальный слой».
2. Claude Code записывает факт → новая сессия Codex воспроизводит его без
   подсказки.
3. Codex обновляет `SESSION.md` → Claude Code на старте излагает содержимое, не
   обращаясь к файлу инструментом (подтверждает работу импорта).
4. Пустой проект без `docs/agent-memory/` → первый агент создаёт структуру и
   шимы самостоятельно.

## Отвергнутые варианты

- **ai-memory** (Rust, Docker, hooks + MCP). Целевой сценарий совпадает, Claude
  Code и Codex поддержаны. Отклонён: v0.2-beta, дополнительный демон с volume,
  требуется ключ Anthropic для консолидации, память вне git, а у Codex
  отсутствуют хуки, на которые он опирается. Не тупик — ai-memory держит
  markdown источником правды и SQLite индексом, поэтому может быть надстроен над
  тем же каталогом позже.
- **memoir** (Python, MCP, ветвление памяти под ветки кода). Отклонён по той же
  причине: инфраструктура ради автоматизации, которую нечем нагрузить при
  текущем объёме в два факта.
- **Serena MCP как общий стор.** Уже подключён к Codex и умеет
  `write_memory`/`read_memory`. Отклонён: `.serena/` находится в `.gitignore`,
  то есть память не версионируется; serena — тяжёлый LSP-сервер, память у него
  побочная функция; состояние работы в его формат укладывается плохо.

Основание выбора: узкое место — единая точка и передача хода, а не объём памяти
и не поиск по ней. Файловый вариант закрывает именно это и дополнительно даёт
историю памяти в git, которой не дают остальные.

## Что не входит в объём

- Автоматический захват наблюдений во время сессии.
- Семантический поиск и эмбеддинги.
- Перенос стора на остальные проекты в `VS_projects` — выполняется бутстрапом по
  мере надобности, отдельной задачей не является.
- Миграция памяти Codex — переносить нечего, стор пуст.
