# Общая память Claude Code и Codex — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude Code и Codex работают с одним стором памяти, поэтому при переключении агента не теряются ни знания о проекте, ни состояние текущей работы.

**Architecture:** Протокол лежит одним экземпляром вне проектов и подключается к обоим агентам глобально. Память проекта — markdown-файлы в самом репозитории (`docs/agent-memory/`), которые Claude Code втягивает через `@`-импорты корневого `CLAUDE.md`, а Codex читает по указанию корневого `AGENTS.md`. Новый проект бутстрапится первым же агентом без ручных действий.

**Tech Stack:** Markdown, git. Никакого рантайма, демонов и зависимостей не добавляется.

**Spec:** [docs/superpowers/specs/2026-08-26-shared-agent-memory-design.md](../specs/2026-08-26-shared-agent-memory-design.md)

## Global Constraints

- Значения секретов (пароли, токены, ключи, содержимое `.env`) в стор не пишутся ни при каких условиях, включая приватный репозиторий. Указатели на них — имя переменной окружения, путь к локальному файлу с доступами, адрес хранилища — пишутся: знания по доступам у Claude Code и Codex должны совпадать.
- Репозиторий `https://github.com/Zheltenkov/MBK_v4` приватный (подтверждено пользователем 26.08.2026). Публикация репозитория требует ревизии стора до открытия.
- Язык всех файлов памяти — русский.
- `SESSION.md` не длиннее 60 строк, без сырых рассуждений и трассировок.
- Коммиты памяти отделены от кода, префикс `docs(memory):`.
- Даты в фактах абсолютные, формат `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`.
- Абсолютные пути windows-стиля: `C:\Users\zvp\...`.
- Команды проверки проекта: `.venv313/Scripts/python -m ruff check .` и `.venv313/Scripts/python -m pytest` (ruff 0.15.12, pytest 8.4.2, конфигов `pyproject.toml`/`setup.cfg`/`pytest.ini` в проекте нет — запуск с дефолтами).
- Проверки, требующие сессии Codex, выполняет пользователь: агент-исполнитель не может запустить чужой CLI. Такие шаги оформлены как просьба к пользователю с точной формулировкой запроса.

## 1. Начало сессии

Если в корне проекта есть каталог `docs/agent-memory/` — прочитай
`docs/agent-memory/MEMORY.md` и `docs/agent-memory/SESSION.md` до первого
действия по задаче.

Если каталога нет — заранее ничего не создавай. Бутстрап (раздел 5)
выполняется в тот момент, когда впервые понадобилось записать факт или

## 2. Состояние работы: SESSION.md

Файл перезаписывается целиком. Append-лог запрещён: история хранится в git, а
растущий файл перестают читать.

Шаблон:

```markdown
# Состояние сессии

Обновлён: ГГГГ-ММ-ДД · Агент: <имя модели> · Ветка: <ветка> · Рабочее дерево: чисто

## Задача
<1–3 предложения: что делаем и зачем>

## Сделано
- <результат> — <файл:строка или хеш коммита>

## Следующий шаг
- <конкретное действие>

## Открытые вопросы
- <вопрос> → ответ нужен от: пользователя / кода / внешней системы

## Не трогать
- <что оставлено намеренно> — <почему>
```

Правила по полям:

- **Шапка.** Дата, агент, ветка, чистота рабочего дерева. Дерево грязное —
  пиши «грязно (N файлов)»: это предупреждение, что часть работы вне коммитов.
- **Задача.** Что делаем и зачем. Не пересказ тикета.
- **Сделано.** Только изменения, реально попавшие в файлы, со ссылкой
  `файл:строка` или хешем коммита. Утверждение без ссылки не пиши —
  принимающий агент не сможет его проверить. Прерванную правку помечай
  «частично», не замалчивай.
- **Следующий шаг.** Конкретное действие, а не направление. «Прогнать
  `pytest tests/test_x.py`», не «продолжить тестирование».
- **Открытые вопросы.** С указанием, от кого нужен ответ. Пустой раздел
  оставляй с прочерком, не удаляй.
- **Не трогать.** То, что выглядит как дефект, но сделано намеренно, и то, что
  ты сознательно не стал менять в этой задаче. Если запись переживёт текущую
  задачу — ей место в `facts/` или в ADR проекта, а не здесь.

Ограничения: не длиннее 60 строк; без сырых рассуждений, трассировок и
секретов.

Когда писать:

- перед переключением на другого агента;
- в конце сессии;
- немедленно, если пользователь сказал «хендофф» или «сохрани состояние».

Конфликт записи: перед перезаписью прочитай шапку. Если поле «Агент» указывает
на другого агента и дата сегодняшняя — не затирай молча. Слей разделы, в шапке
перечисли обоих агентов.

## 3. Факты: facts/*.md и MEMORY.md

Формат файла факта:

```markdown
---
name: <slug-kebab-case>
description: <одна строка, по ней факт находят>
metadata:
  type: project | decision | gotcha | rule | reference
---

<факт>

**Почему:** <обоснование>
**Как применять:** <когда и что делать>

Связано: [[другой-slug]]
```

Типы: `project` — цели и ограничения работы; `decision` — выбрали X вместо Y и
почему; `gotcha` — грабли, на которые уже наступали; `rule` — как здесь принято
делать; `reference` — внешние ссылки, дашборды, тикеты.

Для `decision`, `gotcha` и `rule` строки **Почему** и **Как применять**
обязательны: факт без обоснования через месяц неотличим от суеверия.

`MEMORY.md` — плоский индекс, строка на факт:

```markdown
- [Заголовок](facts/slug.md) — зацепка одной фразой
```

Индекс подгружается в контекст целиком, поэтому содержит только строки-указатели,
без содержания.

Правила записи:

1. Записывай: решение с обоснованием, грабли, договорённость, внешний ресурс.
2. Не записывай: то, что видно в коде или `git log`; то, что живёт одну сессию;
   значения секретов — пароли, токены, ключи, содержимое `.env`.
   Указатели записывать можно и нужно: имя переменной окружения, путь к
   локальному файлу с доступами, адрес хранилища. Без них принимающий агент не
   знает, где брать учётные данные, и передача хода получается неполной.
3. Перед созданием файла ищи существующий по теме. Обновляй его, не заводи
   второй.
4. Неверный факт удаляй вместе со строкой индекса. Пометками «устарело» не
   пользуйся: мёртвые факты хуже отсутствующих.
5. Даты абсолютные, не относительные.
6. Если в проекте есть каталог архитектурных решений (`docs/adr/` или
   аналогичный) — крупные решения остаются там, а в `facts/` для них создаётся
   указатель типа `reference`. Копий не делай.
7. Индекс и каталог фактов держи согласованными. Файл в `facts/` без строки в
   `MEMORY.md` невидим: Claude Code подгружает в контекст только индекс.
   Заметил расхождение — исправь сразу, не откладывая на потом.

## 4. Что в стор не попадает

- Личное о пользователе: кто он, как с ним работать, его предпочтения. Это
  остаётся в личной памяти агента, потому что репозиторий клонируется и
  шарится.
- Значения секретов: пароли, токены, ключи, содержимое `.env`. Указатели на них
  (переменная окружения, путь к файлу, адрес хранилища) — можно.
- Транскрипты и сырые рассуждения.
