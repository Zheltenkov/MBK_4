Backend заказчика (Андрей Васин) с 27.08.2026 вносит правки **прямо в
`custom/vendor-src/` своего репозитория** `mbk/mbk_ai`, коммитит в `main` и
собирает образ с суффиксом сборки: `1.0.7-mbk1`, `-mbk2`, `-mbk3`. Изменения
описывает в `custom/README.md`, раздел «Патч МБК поверх <версии>». Ветка `dev`
после мержа удаляется — актуален только `main`.

**Порядок работы, который из этого следует.** Перед любой новой поставкой:

1. клонировать их `main` и сравнить `custom/vendor-src/` с нашим деревом;
2. перенести их правки к нам и закоммитить у себя;
3. только потом гнать `sync_vendor.py` и открывать MR.

Пропуск первого шага — не мелочь: скрипт синка копирует наше дерево поверх
`vendor-src` целиком, поэтому следующий MR **молча откатит их исправления**.
27.08.2026 среди них была починка падения в бою.

MR открывать через API с `assignee_id` и `reviewer_ids` на `vasin` (id=2). Без
назначения MR к нему не попадает: 25.08.2026 он не увидел `!6` и просил
сделать MR, который уже был открыт.

Доступ к их GitLab — см. [[mbk-production-setup]]; токен лежит в
`gitlab_acsess.txt` в корне репозитория (файл в `.gitignore`).
