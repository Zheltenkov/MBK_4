# Кнопка согласия на офер-странице

Что должна делать страница, чтобы согласие клиента доехало до CRM. Схема
согласована 21.08.2026; бот со своей стороны готов.

## Как это выглядит целиком

1. Клиент проходит анкету в чате и оставляет телефон.
2. Квалификация возвращает `need_site_consent = true` — **лид не отправляется**,
   бот держит его у себя.
3. Бот даёт клиенту ссылку на офер-страницу, дописав к ней четыре параметра.
4. Клиент нажимает на странице кнопку согласия.
5. Страница зовёт адрес из параметра `url`, передав `d_lead_id`.
6. Бэкенд МБК вызывает бота, бот отправляет лид в CRM **с согласием** и
   возвращает адрес финальной страницы.
7. Не нажали за 5 минут — бот отправляет лид без согласия, и роутер уводит
   его в колл-центр.

## Что бот дописывает к ссылке

Правило зависит от того, откуда взялся адрес.

**Постоянная страница** из `MBK_SITE_CONSENT_DEFAULT_URL` уходит клиенту **как
есть, без единого параметра**. Она узнаёт клиента по куке `mbk_chat_consent`,
которую ставит виджет, а `d_lead_id` у неё занят под свой формат: её код
декодирует этот параметр как base64 с числовым идентификатором лида и на нашем
hex-номере сессии отвечает 500 (backend заказчика, 26.08.2026).

**Офер-страница, которую вернула CRM** в `thanks_url`, получает параметры —
она читает клиента из адреса. К ней добавляются:

| Параметр | Что в нём | Пример |
|---|---|---|
| `d_lead_id` | номер сессии — его и надо вернуть | `a1b2c3d4e5f6` |
| `url` | адрес, который страница должна позвать | `https://www.mbk.ru/api/chat-consent` |
| `thanks_url` | куда вести клиента после нажатия | `https://www.mbk.ru/thanks` |
| `fio` | имя клиента для приветствия | `Пётр` |

Собственные параметры адреса и якорь сохраняются, значения закодированы.

Пример готовой ссылки:

```
https://info.mbk.ru/spasibo-zaim-zalog-pts?fio=%D0%9F%D1%91%D1%82%D1%80
  &d_lead_id=a1b2c3d4e5f6
  &url=https%3A%2F%2Fwww.mbk.ru%2Fapi%2Fchat-consent
  &thanks_url=https%3A%2F%2Fwww.mbk.ru%2Fthanks
```

`fio` страница уже умеет — подставляет имя в заголовок вместо «Маргарита
Ивановна». Остальные три пока не читает.

## Что нужно добавить на страницу

Кнопку, которая по нажатию делает один запрос:

```js
const params = new URLSearchParams(location.search);
const leadId = params.get('d_lead_id');
const endpoint = params.get('url');
const thanks = params.get('thanks_url');

if (!leadId || !endpoint) return;   // пришли не из чата — кнопку не показываем

const response = await fetch(endpoint, {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({session_id: leadId}),
});
const result = await response.json();
location.href = result.thanksUrl || thanks;
```

Три правила:

**Только по нажатию.** Не при загрузке страницы: предпросмотр ссылки в
мессенджере откроет её сам и даст согласие за клиента.

**Кнопка нужна только при наличии `d_lead_id`.** Без него человек пришёл не из
чата, и подтверждать нечего.

**Повторное нажатие безопасно.** Бот отправит лид один раз, ответ будет тем же.

## Что делает бэкенд МБК

`https://www.mbk.ru/api/chat-consent` принимает `{"session_id": "..."}` и
переправляет его боту:

```
POST http://<адрес бота>/api/site-consent
Content-Type: application/json

{"session_id": "a1b2c3d4e5f6"}
```

Ответ бота:

```json
{"success": true, "thanksUrl": "https://www.mbk.ru/thanks"}
```

Другие ответы: `404` — такой сессии нет или лид по ней уже отправлен (например,
истекли 5 минут); `403` — только если включено ограничение по адресу и запрос
пришёл не с него. Оба случая для страницы означают одно: вести клиента на
`thanks_url` из параметров.

## Настройки на стороне бота

| Переменная | Зачем |
|---|---|
| `MBK_SITE_CONSENT_PAUSE_ENABLED` | Включает всю схему. **Включать, когда кнопка появится на страницах**: до этого лид уходит сразу, как раньше |
| `MBK_SITE_CONSENT_ALLOWED_IPS` | Необязательное ограничение по адресу отправителя. Пусто — принимаем откуда угодно |
| `MBK_SITE_CONSENT_TIMEOUT_SECONDS` | Сколько ждём нажатия, по умолчанию 300 — как у анкетного крона `not-confirm-bfl` и таймера самой офер-страницы |
| `MBK_SITE_CONSENT_CALLBACK_URL` | Что кладём в параметр `url` |
| `MBK_SITE_CONSENT_DEFAULT_URL` | Офер-страница, когда CRM своей не вернула. Пусто — такой лид уходит сразу |
| `MBK_SITE_CONSENT_BUTTON_PAGES` | Страницы, где кнопка есть. Пауза только для них. Пусто — не ограничиваем |

Пароля у эндпоинта нет, и ограничение по адресу выключено по умолчанию:
внутри контейнеров адрес отправителя не постоянен — к боту приходит шлюз
docker-сети, который меняется при пересоздании стека.

Что защищает вместо этого: согласие принимается только для сессии, которая
действительно ждёт нажатия, и только один раз. Номер сессии случайный и
попадает в чужие руки лишь вместе с самой офер-ссылкой. Каждое принятое
согласие пишется в лог вместе с адресом отправителя.

Если адрес однажды станет постоянным, ограничение включается одной строкой в
`MBK_SITE_CONSENT_ALLOWED_IPS`.

## Чего не хватает, чтобы включить

**Кнопки на офер-страницах.** Проверено 21.08.2026:
`info.mbk.ru/spasibo-zaim-zalog-pts` отвечает, `fio` подставляет, но
`d_lead_id`, `url` и `thanks_url` не читает.

**Адреса офер-страницы для БФЛ.** Если у маршрута в `thanks_url` пусто, бот
ведёт клиента на общую страницу благодарности, а там кнопки нет и быть не
может. Такие лиды бот отправляет сразу и помечает «шаг не показывался» — то
есть ждать никого не заставляет. В логе такие случаи видны отдельной строкой.

Постоянный адрес вписывается в `MBK_SITE_CONSENT_DEFAULT_URL` — тогда клиент
БФЛ получит ссылку на него, а не на общую благодарность.

## Как страница узнаёт клиента

Backend МБК 25.08.2026: когда бот выдаёт ссылку, виджет ставит куку
`mbk_chat_consent = session_id` на домене `www.mbk.ru`. Клиент открывает
офер-страницу, жмёт кнопку, guard читает куку и пересылает нам этот номер
сессии. Сама страница про клиента ничего не знает.

Из этого следуют две вещи.

**Кука видна только своему домену.** Офер на другом хосте клиента не узнает,
и кнопка там работать не будет. Поэтому паузу включаем только для страниц из
`MBK_SITE_CONSENT_BUTTON_PAGES`; всё остальное уходит сразу, как раньше.

**Куки может не быть.** Ссылку открыли в другом браузере или из превью в
мессенджере — тогда согласие взять неоткуда, и лид уйдёт через пять минут
с отметкой «не подтвердил». На постоянной странице подстраховаться параметром
нельзя: `d_lead_id` там занят. Если однажды освободится место под наш номер
сессии под другим именем — скажите, впишем.
