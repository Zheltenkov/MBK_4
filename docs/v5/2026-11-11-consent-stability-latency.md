## Причина

В предыдущем R3 на реплике «Да, согласен на передачу специалисту. Телефон
я уже оставил выше» C ошибочно вернул decline_transfer. Защита правильно
отвергла неподтверждённый отказ, но общий strict safe забраковал одновременно
интерпретацию клиента и исходящий ответ. G2/C2 заново обрабатывали ту же
входную реплику, хотя смена ответа не исправляет её классификацию.
Тот ход занял21.043s. Это воспроизведённый механизм, не оценка его частоты.

## Изменение контракта

- policy_semantics.py: strict safe остаётся прежним. outgoing_safe отдельно
  проверяет привязанный claims-канал относительно итогового консервативного
  frame. user_issues и claims_issues сохраняются отдельно. Неподтверждённая
  новая подсказка user-канала не меняет цель; прежняя цель кода сохраняется.
- policy_grounded_voice.py v15: только для единственной ошибки
  user_refusal_unbound допускается оставить точный G1. Нужны raw и effective
  C style accept, полный claims-канал, неизменность текста, code guards и
  supported F там, где он требуется. Отсутствующий/сломанный канал либо
  несовпавший digest этого разрешения не дают.
- Новая ветка не разрешает сбор полей или подтверждение решения. Повторная
  проверка без ожидаемого поля ограничивает речь, не меняя фактический план.
  Отдельный консервативный запрет decision/receipt слов страхует all-null
  claims C; это узкий ограничитель, не универсальное понимание языка.
- Ошибочный raw C не переписывается. user_valid остаётся false, состояние
  paused, актов и полномочий нет. Эта пауза может сохраняться между ходами;
  независимый FAQ остаётся возможен. Автоматического восстановления согласия нет.
- policy_semantic_analysis.py: явно задан negative-only enum. Положительное
  решение без самостоятельного отказа означает acts:[], а положительное
  вступление не отменяет следующий реальный отказ. Два сбалансированных
  примера отличаются от замороженного проверочного текста.

Persona Ники, G prompts, модели, C/F таймауты, источники, формальное согласие
и отправка не менялись. Дополнительные примеры C увеличивают входной контекст;
общий выигрыш скорости требует измерения, а не выводится из числа правок.
