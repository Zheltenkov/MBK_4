# Телефон, резервный ответ и область списания — 11.11.2026

Продолжение A2 по трём замечаниям предыдущего полного Polza-прогона:
связь телефона с сохранением анкеты после пропуска C2; общий резерв вместо
ответа о сохранённой сумме при C deadline; полное списание без сохранения
судебного порядка и условий из источника. Работа только в локальном контуре.

## Решение

Обычная генерация остаётся G → C → применимый F; новых моделей и проверяющих
LLM нет. Отдельные ограничения реализуются в существующих слоях:

- `policy_content.py`: связь просьбы о телефоне/его необходимости с целью
  сохранения ответов проверяется кодом, независимо от заполнения C slots.
  Применяется существующий `phone_required_to_save_chat` и прежний bounded
  repair. Обычное назначение контакта для связи и отрицание зависимости
  сохранения от телефона не становятся нарушением.
- `policy_factual_audit.py`: область положительного утверждения о списании
  проверяется через существующий material/source-context механизм.
  Уточнения вида процедуры, условий и возможности результата нельзя терять
  при сокращении. Подтверждённая возможность не превращается в обещание.
  Привязка к конкретным source IDs сохраняется; новых фактов в каталог нет.
- `policy_grounded_voice.py`: при неудачной проверке прямой цельный вопрос
  о текущей учитываемой сумме может получить проекцию подтверждённого
  `facts.debts.total`. Нужны code-owned known intent/amount, целое ограниченное
  число и отсутствие подтверждения кандидата, offer/closing и onloader.
  Сумма из latest, сумма кредита, цитата, новое действие или смешанная реплика
  этот путь не выбирают. Пауза, отказ, курсор и факты не меняются.
- `prompts.py`: контакт объясняется связью по обращению, без обещания звонка
  или передачи. Для объяснения списания сохраняются существенные оговорки
  источника. Новая инструкция не задаёт готовые обычные реплики.

Узкий резерв по сумме — только безопасная деградация после сбоя. Успешный
модельный ответ остаётся свободным; нового универсального FAQ движка нет.
Прежние A1 запрет контакта при паузе и A2 unknown-docs сохраняются.
AST-проверка подтверждает неизменность CONVERSATION_SYSTEM_PROMPT,
STYLE_EXAMPLES и policy_verified_context. Модели, схема и таймауты прежние.

## Открытые замечания

Общий conversational/style PASS не заявляется. Критик отметил четыре
оставшихся проявления известных речевых/recovery ограничений:

- money/u07 повторяет вопрос о долговой цели после явного выбора клиента;
- money/u08 на согласие отвечает неуместной темой отмены заявки/удаления номера;
  это речевая ошибка, согласие/No/backend delivery этим не созданы;
- control/u02 повторно уточняет состав уже точного общего долга400000;
- money/u09 после malformed C получает прежний code hold вместо содержательного
  ответа о неподтверждённых документах; типовой список при этом не придуман.

Эти пути не объявлены исправленными тремя целевыми изменениями. Повтор вопроса
и неуместный ответ способны мешать разговору; влияния на конверсию этим
локальным прогоном не измеряли. Есть краткое формальное квитирование профиля,
поэтому сохранение persona не приравнивается к безупречности каждого ответа.

Независимый итог — scoped GO трём фиксам для локального обновления:
`independent-final-review.md/.json`. Критик прочитал все raw G/E/C/F, served,
состояние и SSE, сверил pins. После его GO ручная Ника обновлена:
http://127.0.0.1:8891/; backend8890/UI8891 HTTP200,8893 остановлен.
Все7 сессий с ревизиями и ключ точно совпали до/после restart
(`manual-restart.json`). После refresh новых модельных запросов не делали.

Нельзя выводить production SLA, качество всех перефразировок, юридическую
пригодность конкретного клиента или рост конверсии из одного такого прогона.
Боевой сервер, Git remote, отправка лидов и согласие на доставку не изменяются.
