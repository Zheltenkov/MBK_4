# Независимая оценка получения текущей анкеты, этап 1

Дата: 06.11.2026. Область: серверная авторизация текущего обращения, чтение
истории CRM, использование фактов в диалоге и запрет новой отправки.
Проверяются контракты и реальные локальные границы вызова. Подключение к
боевому источнику анкет, реальные ответы модели и коммерческая отправка в этот
этап не входят.

Итог повторного изолированного прогона: **baseline 51/51, мутации 27/27
обнаружены**, ошибок сбора/фикстур 0. Собственные независимые тесты: **46/46**;
ещё 5 baseline-проверок используют исправленный настоящий redirect transport.
Финальная связанная выборка с тестами пакета и HTTP attachment: **116/116**;
`ruff check .` и `pyright` — без ошибок. После прогона SHA256 всех скопированных
исходников и тестов повторно сравнены с checkout: изменений нет.

## Рубрика приёмки

| Инвариант | Наблюдаемое поведение | Проверка |
| --- | --- | --- |
| Браузер не задаёт личность клиента | Неверная подпись, другая сессия, просроченная или будущая capability не вызывают источник | Счётчики `Source.fetch` и `Transport.post` |
| Привязку нельзя заменить | Другая анкета/subject/revision, неактивная запись, конфликт привязки отклоняются | Отдельные несовпадения каждого идентификатора, сохранение исходной привязки |
| Снимок актуален в момент использования | Задержка источника и новая capability не продлевают срок старого снимка; ровно 300 секунд уже просрочено | Управляемые часы; HTTP и квота ещё не затронуты |
| Неизвестное не превращается в нового клиента | Нет записи, отказ, таймаут, 429, неполная история остаются разными исходами | Ловушка на создание замены; один логический lookup — максимум один HTTP-вызов |
| Квота ограничивает реальные попытки | Последняя разрешённая попытка проходит, следующая блокируется; таймаут не возвращает квоту | Общая SQLite, 24 конкурентных экземпляра, граница скользящих суток |
| История не подменяет текущую анкету | Историческая сумма/произвольный текст не меняют текущие факты и не попадают в публичную проекцию | Синтетическая заметка-инструкция, неизменность текущей анкеты |
| Известные факты используются | Имя, телефон, возраст и текущая запрошенная сумма не запрашиваются следующим шагом повторно | Настоящий планировщик; пустая контрольная анкета продолжает спрашивать имя |
| Отсутствующее не считается нулём или отказом | Нет долга, долг 0, сумма желаемого кредита — разные данные; неизвестные активы не становятся `false` | Раздельные контрактные примеры |
| Частные данные не достигают модели | Адрес/имя без узнаваемого шаблона, известный телефон из новой реплики, ссылки и digest отсутствуют в сообщениях модели даже при общем флаге PII=false | Шпионы после сборки сообщений `stream_conversation` и `extract_facts`; безопасная сумма 400000 сохранена |
| Чтение контекста не создаёт вторую заявку | Любое наличие контекста, включая `None`, блокирует completed/abandoned intake | 12 сценариев, счётчик вызовов; такой же обычный клиент вызывает intake ровно один раз |
| Bearer не следует за redirect | 301/302/303/307/308 не вызывают второй сервер | Настоящий HTTP transport и два временных локальных сервера |

## Тесты и изоляция

Независимые тесты:

- `tests/test_site_context_acceptance.py`: 32 проверки серверного контракта,
  свежести, исходов чтения, квоты и использования фактов.
- `tests/test_site_context_llm_acceptance.py`: 2 проверки фактических сообщений
  модели — conversation и extraction. Оригинальное backend-состояние должно
  остаться неизменным.
- `tests/test_site_context_submission_acceptance.py`: 12 проверок реального
  intake-координатора с положительным контролем работоспособности отправки.

`evaluation/site_context_guard_mutations.py` копирует только исходники и данные
Python-пакетов в отдельный системный временный каталог. `.env`, файлы доступов,
журналы и базы checkout не копируются. До импорта pytest блокируются DNS и
подключения; разрешены только порты loopback-серверов, которые создал сам
процесс теста. Значения ключей и прокси из окружения удаляются.

Каждая мутация запускается отдельным subprocess над собственной копией.
Перед мутациями обязателен зелёный baseline. `killed` означает pytest exit 1,
хотя бы одно падение тела теста и отсутствие ошибок фикстур/сбора. Ошибка импорта
или неподходящий текстовый anchor не считается обнаруженным дефектом. Отчёт
сохраняет SHA256 исходников, имена упавших тестов и число вызовов через assertions,
не сохраняя содержимое ответов CRM, capability или телефоны. Тип исключения
внутри тела теста runner отдельно не классифицирует; семантика всех 27 текущих
изменений и имена соответствующих падений проверены при независимом review.

## Что обнаружено во время проверки

1. Срок capability сначала мог продлить использование старого снимка. Проверка
   с наблюдением 299 секунд назад и lookup через секунду показала дефект.
   Исправление владельца пакета ограничивает handle минимумом срока capability
   и срока свежести снимка. Повторный запрос должен быть отклонён до HTTP и квоты.
2. При проекции фактов перед маскированием терялись исходные значения контакта.
   Независимый шпион увидел известный телефон в последней реплике; свободные
   адреса и имя тоже требовали закрытой проекции. Исправление владельца интеграции
   сначала маскирует по исходным частным значениям, затем закрывает набор фактов
   для модели. Оба настоящих model-message boundary теста проходят.
3. Первый тест перенаправлений был недостаточным: его shim отклонял любой второй
   URL и тем самым скрывал удаление `_NoRedirect`. Первый отчёт честно содержит
   **20/21**, один выживший mutant. Исправленный shim переписывает только исходный
   адрес; настоящий follow-up к локальному серверу проходит через urllib.
   Независимый отрицательный контроль подтвердил передачу Bearer у уязвимого
   opener и отсутствие второго запроса у исправленного.

Исходный отрицательный результат сохранён:
`logs/site-context-2026-11-06/guard-mutations.json`. Его нельзя цитировать как
успешный полный прогон. Финальный прогон и точные хеши:
`logs/site-context-2026-11-06/guard-mutations-final.json`.

## Воспроизведение

```powershell
.venv313/Scripts/python -m pytest -q tests/test_site_context_acceptance.py tests/test_site_context_llm_acceptance.py tests/test_site_context_submission_acceptance.py
.venv313/Scripts/python -m evaluation.site_context_guard_mutations --out logs/site-context-2026-11-06/guard-mutations-final.json
```

Мутации удаляют проверку подписи/сессии/срока/привязки/активности, обходят
квоту, меняют timeout/forbidden на «нет истории», повторяют 429, публикуют
историю, превращают кредит в долг или отсутствие в ноль, создают замену
отсутствующей заявки, снимают delivery hold и закрытую проекцию для модели.
Это целевые изменения поведения; процент не является полнотой всех возможных
дефектов или оценкой качества живых ответов LLM.

## Граница результата

Все проверки синтетические. Новые capability issuer и реальный read-only
источник текущих анкет ещё должны быть подключены по подтверждённому контракту;
функция по умолчанию выключена. Shared SQLite доказывает квоту только для
процессов, использующих общий файл, и не заменяет общий лимит upstream для
прочих клиентов. При раздельных репликах нужен общий бюджет или выключенный
lookup. В этом этапе любая context-сессия намеренно удерживает отправку до
отдельного согласования владельца доставки и согласия клиента.
