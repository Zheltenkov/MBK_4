## Передача изменений — правило пользователя от 11.11.2026

- Прямой доступ к боевому серверу запрещён. К нему не подключаться, команды
  на нём не выполнять, настройки и контейнеры не менять. Старые инструкции
  выкатки и сохранённые доступы не разрешают такие действия.
- Изменения готовить в ветке `dev` соответствующего репозитория. Если ветки
  нет, создать её. Передача изменений идёт через MR на рассмотрение Андрею.
- Сообщения коммитов писать кратко и по существу. Перед отправкой показать
  пользователю состав изменений и сообщения коммитов, получить его согласование.
  До согласования изменения в удалённый репозиторий не отправлять.
- Разработка, запуск и проверки выполняются локально.

Проверено 02.11.2026: `pyproject.toml`, `setup.cfg`, `pytest.ini` отсутствуют;
ruff/pytest используют дефолты. Типы настроены в `pyrightconfig.json`,
pyright установлен по версии из `requirements-dev.txt`. Перед запуском
проверяй актуальную конфигурацию; target Python в pyright не менять молча.

## Границы

- Архитектурные решения — `docs/adr/`. В `docs/agent-memory/facts/` для них
  только указатель типа `reference`, копий текста не делать.
- `docs/HANDOVER.md` — передача системы разработчику МБК, документ для человека.
  Состояние работы агентов — `docs/agent-memory/SESSION.md`. Файлы не путать и
  не сливать.
- Репозиторий приватный, и стор памяти рассчитан на это. В стор не записывать
  **значения** секретов: пароли, токены, ключи, содержимое `.env`. Указатели
  записывать нужно — имя переменной окружения, путь к локальному файлу с
  доступами, адрес хранилища: у Claude Code и Codex должны быть одинаковые
  знания по доступам. Если репозиторий будут открывать — сначала ревизия
  `docs/agent-memory/`.
